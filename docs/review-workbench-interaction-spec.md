# 逐页策展工作台交互规格

本规格汇总“逐页审核界面的交互规格”“使用真实 AnyDoc 输出测量逐页策展耗时”“按需截图交互如何做到不经讲解即可完成”和“初版如何兜底人工策展吞吐”四项决议。它记录已选定的 C 版构图、用户确认后的“AnyDoc 来源优先”审核顺序、真实页面走查暴露的问题、经同一策展人员确认的按需截图交互，以及初版提效能力的人工确认边界。

## 1. 目标与边界

工作台服务于熟悉材料的内部策展人员。首版以 1440px 桌面和键盘流为主，在 1280px 下仍保持三栏可用；移动端不在本票范围内。

工作台的目标不是自动替人决定内容，而是让人能在同一视野内完成以下闭环：

1. 对照标准页渲染，先审核 AnyDoc 直接提取的文字与图片源文件。
2. 只有来源不足以表达页面信息时，才手动画框补充截图。
3. 编辑源图片或截图的 `summary`，清空硬校验后批准或排除页面。
4. 记录包含查看、来源审核、可选截图、标注与页级结论在内的总耗时和阶段耗时，为后续流程改进保留事实。

原型是单个原生 HTML/CSS/JavaScript 文件，无后端、无持久化。公开内容均为合成样本；从本机载入的 PNG、JPEG 或 WebP 只生成浏览器内存 URL，不上传、不记录文件名。当前静态原型用合成 AnyDoc 数据验证流程，尚未连接真实 AnyDoc 输出。

## 2. 已选构图

采用「页列、画面与纵向日志」：

| 区域 | 1440px 目标占比 | 职责 |
| --- | ---: | --- |
| 左侧页列 | 约 14% | 队列筛选、页码直达、缩略预览、批量选择 |
| 中央画面 | 约 56% | 标准页渲染；来源审核完成后承载可选截图框 |
| 右侧纵向日志 | 约 30% | 默认展示 AnyDoc 文字与图片源文件；第二页签只保留截图状态与对象摘要；底部固定审核闸门 |
| 底部命令条 | 固定高度 | 高频快捷键与保存状态 |

视觉语法采用「样片审看室」：中性监看器黑承载来源页，明亮场记纸承载审核记录，teal 表示当前选择，amber 表示待确认，red 表示排除。颜色始终与文字、图形或状态名共同出现。

1280px 时三栏缩为 178px / 可伸缩中央区 / 352px；页面无横向溢出。右侧日志独立滚动，中央来源页不会因长表单被推出首屏。

## 3. 信息模型

### 3.1 页面

页面在策展队列中的审核状态只有：

| 状态 | 可编辑 | 进入方式 | 离开方式 |
| --- | --- | --- | --- |
| `pending` | 是 | 新页、变化页、人工重开、隐藏页启用 | 批准为 `approved`；带原因排除为 `excluded` |
| `approved` | 否 | 硬校验全部通过后批准 | 人工“重新打开”为 `pending` |
| `excluded` | 否 | 选择页级排除原因后排除 | 人工“重新打开”为 `pending` |

隐藏页不是第四种审核结论。它默认只登记为 `hidden`，不进入待处理队列；人工选择“启用并处理此页”后才转为 `pending`。

页面保留可选 `overview`、只读演讲者备注、整页排除原因与补充说明。渲染质量警告需在版本发布前显式确认，但不阻止页内审核或形成页级结论。

### 3.2 AnyDoc 来源审核

每次进入 `pending` 页，右侧默认打开“AnyDoc 来源”，中央页不显示任何自动候选框。来源审核分两类证据：

- **文字提取**：展示 AnyDoc 的当前页原文；人可修订并显式确认。修改已确认文字会立即撤销确认。
- **图片源文件**：逐个展示稳定编号、原始文件名、格式、尺寸和预览。人选择“保留源文件”或“忽略”。

源图片处置规则：

| 处置 | 必填 | 结果 |
| --- | --- | --- |
| 保留源文件 | `summary` | 原始图片文件及人工标注进入产物 |
| 忽略 | 忽略原因 | 文件不进入产物，但保留人工处置审计信息 |

文字与全部源图片处置完整后，人才能点击“完成来源审核”。任何来源字段之后被修改，`sourceReviewConfirmed` 立即回到 `false`，画框入口重新锁定。

### 3.3 按需截图视觉对象

截图不是进入页面时的默认识别结果。只有 `sourceReviewConfirmed = true` 后，中央画面才显示一次明确决策：“来源完整，直接审核”或“有缺口，在页面上框选”。选择零截图路径不会创建空的视觉对象；选择画框路径后，人在中央页面拖拽创建视觉对象。

松开指针后，系统立即为临时视觉对象分配可见的两位编号，并在不遮挡框选内容的位置打开上下文浮窗。当前框选保持原亮度和高对比边界，其余工作台轻度降噪；浮窗优先位于框选右侧，空间不足时依次换到左、下、上方，并保持至少 14px 间隔。浮窗只承载当前对象的 `summary` 与可选 `visual_type`，右侧截图页签不重复完整表单。

手动画框本身即表示“有必要纳入”，因此不再要求对截图对象二次选择纳入或排除。对象支持：

- 拖动或键盘微调位置。
- 拖动右下角或键盘调整尺寸。
- 合并相邻截图。
- 上移、下移或按页面位置排序，改变 `visuals[]` 的阅读顺序。
- 删除不再需要的截图。

每个截图对象保留稳定、可见的两位编号，并在中央定位框、上下文浮窗与右侧对象摘要间一一对应。截图必须填写 `summary`，`visual_type` 可选。页面可以完全没有截图；若 AnyDoc 来源已经足够，零截图是合法、可批准的状态。

### 3.4 VLM 边界

初版不包含 VLM 能力：不提供生成入口、快捷键、批量预生成、草稿存储、生成任务或与草稿相关的审核状态和阻塞。现有原型中的 VLM 草稿控件属于早期探索，不是初版实现输入。

若未来另行引入 VLM，仍受既有人工质量边界约束：只能由人显式触发，草稿与正式标注分离，每个草稿必须由人逐项查看并确认或丢弃；不得自动生成视觉对象、批量确认草稿或自动批准页面。未来能力不要求初版预建闲置接口、数据模型或隐藏功能。

## 4. 核心流程

### 4.1 进入队列

默认筛选为“待处理”。未变化且已继承的页面不占用主队列，可在“已继承”或“全部”中查看。变化页在页列中同时显示“待审核”和“已变化”。

进入一页时：

- 启动该页计时。
- 默认打开“AnyDoc 来源”页签。
- 中央只呈现标准页渲染，不显示任何自动候选框。
- “画框截图”与“合并截图”保持禁用。
- 不显示或触发模型草稿能力。

### 4.2 来源优先路径

推荐顺序：

1. 对照中央标准页，核对或修订 AnyDoc 文字并确认。
2. 逐个检查图片源文件，保留时填写 `summary`，忽略时选择原因。
3. 点击“完成来源审核”。
4. 判断来源是否已经完整：若是，直接批准；若否，再进入“按需截图”。

### 4.3 可选截图路径

来源审核完成后：

1. 在中央画面判断来源是否仍有缺口；来源完整时选择“直接审核”，不切换到额外表单，也不创建视觉对象。
2. 有缺口时选择“在页面上框选”，并在中央页拖出缺失的组合视觉范围。
3. 松开指针后，框选被聚光保留，上下文浮窗自动在不遮挡框选的位置打开，焦点直接落在 `summary`。
4. 填写必填 `summary`，需要时选择 `visual_type`；空 `summary` 保存时留在浮窗内显示错误并重新聚焦输入框。
5. 点击“保存并返回审核”后关闭浮窗，右栏只增加一行对象摘要，硬阻塞即时清零，焦点转移到“批准并前进”。
6. 需要补充更多视觉对象时选择“再截一个”；需要修改已保存对象时，从画面指引或右栏摘要重新打开同一上下文浮窗。

取消语义必须可预测：

- 首个新框在浮窗中取消或按 `Esc`，删除临时对象并回到中央二选一决策。
- 追加新框时取消，只删除本次临时对象，恢复已有对象的完成态。
- 编辑已保存对象时按 `Esc` 或“放弃修改”，保留原值并回到保存态。

浮窗打开期间，浮窗以外的工作台控件进入受保护焦点状态，全局审核快捷键暂停。视口尺寸变化、空值错误展开或框选靠近边缘时必须重新计算位置；在 1440 × 1024 与 1280 × 900 下，浮窗不得遮挡当前框选、裁切底部动作或造成横向溢出。

### 4.4 审核闸门

审核闸门集中显示所有硬阻塞。以下情况阻止批准：

- AnyDoc 文字尚未确认。
- 任一源图片尚未选择保留或忽略。
- 保留的源图片缺少 `summary`。
- 忽略的源图片缺少忽略原因。
- 来源字段完整但尚未点击“完成来源审核”。
- 任一手动画框截图缺少 `summary`。

不存在“至少一个截图”的要求。写作风格、页级 `overview` 和截图数量只提示，不阻止批准。

审核闸门固定在右栏底部。点击“批准并前进”后，当前页转为 `approved`、记录耗时并进入下一 `pending` 页。点击“排除并前进”前必须选择页级排除原因。`approved` 或 `excluded` 页全部锁定，只有“重新打开”才能恢复编辑。

### 4.5 批量操作、标注辅助与页对应确认

页列允许批量选择。批量排除只作用于所选 `pending` 页，并要求先选择统一排除原因；系统仍为每页分别记录排除事件。初版不提供批量批准、批量确认来源或批量套用标注内容，任何会使页进入 `approved` 的操作都必须逐页完成。

标注辅助只提供稳定的字段结构、写作提示和好坏示例，不提供包含事实内容的跨页模板、自动补全文本或一键复制到多页。未变化页通过页指纹继承既有标注；变化页可以按状态机规则展示旧标注作为待确认预填，但必须逐页复核，不能把它视作模板套用。

新版本处于 `awaiting_mapping` 时，页对应模式保持模态门禁。歧义项同时展示新版本源页、候选旧页、SlideID、相邻页证据、相对顺序偏移和页指纹变化；全部确认后才返回工作台。

## 5. 键盘与焦点

| 按键 | 动作 |
| --- | --- |
| `←` / `→` | 上一页 / 下一页 |
| `A` | 批准当前页 |
| `X` | 排除当前页 |
| `R` | 重新打开当前页 |
| `Esc` | 退出画框模式、取消新截图浮窗、放弃已保存截图的浮窗修改，或关闭状态抽屉 |
| `Shift` + 方向键 | 微调当前截图位置 |
| `Alt` + 方向键 | 微调当前截图宽高 |

当焦点位于 `input`、`textarea` 或 `select` 时，全局快捷键不响应；截图上下文浮窗打开时，浮窗以外区域不可聚焦或操作。所有状态必须有可读名称，焦点使用高对比轮廓，按钮禁用状态不能只通过降低颜色饱和度表达。

## 6. 运行事实与状态导出

计时从进入页面开始，在批准或排除时结束。离开未完成页面时累计当前阶段的本次停留，重新进入后继续累计。除整页总耗时外，按当前交互状态累计以下阶段：

- `source_review`：从进入页到完成来源审核，包含查看标准页渲染、核对或修订 AnyDoc 文字及逐个处置图片源文件；来源修改导致确认失效后，后续返工继续累计在此阶段。
- `capture_annotation`：进入画框模式后，画框、裁剪、合并、排序和填写截图标注的累计时间；零截图页该值为零。
- `page_decision`：来源已确认且未在编辑截图时，检查阻塞并批准或排除页的累计时间。

每次完成写入页码、总秒数、各阶段秒数、审核结论、源图片数量及其处置数、截图对象数量和动作计数。顶栏可以显示本次会话的完成页平均秒数；状态导出暴露相应的逐页计时与动作日志。批量排除为每一页单独记录，并以 `mode: "batch"` 标明来源。

队列层面记录采样时刻的 `pending` 页数量和其中最长等待时间。上述数据只用于观察真实流程、识别反复出现的长尾并为未来扩展提供事实；初版不定义告警阈值、产能目标、工时预算、SLA 或自动扩展触发器。

浏览器自动化烟测只验证运行事实会生成，不代表人的处理速度。真实耗时只采用策展人员的本地真实页走查结果，当前 5 页样本不得外推为稳定人均产能、工时预算或 SLA。

## 7. 人工验收脚本与结果

已使用 5 张本地真实页和真实 AnyDoc 输出完成第一轮走查。后续实现回归建议扩展到 5–10 张本地真实页渲染，至少覆盖：纯文字页、含独立图片源文件页、需要保留组合视觉的页面、演讲者备注、未变化继承页、变化页和隐藏页。

1. 打开原型，在“载入本地页”中选择本机 PNG、JPEG 或 WebP。
2. 完成一页 AnyDoc 文字与图片源文件审核，在零截图状态直接批准。
3. 另选一页完成来源审核后，按需画出至少一个截图并填写 `summary`。
4. 带原因排除一页、重新打开一页，验证隐藏页只有启用后才进入队列。
5. 选择多张 `pending` 页，以统一原因批量排除；确认界面不存在批量批准、批量确认来源或批量套用标注内容的入口。
6. 完成一项页对应确认。
7. 打开状态导出，确认每页总耗时、各阶段耗时、源图片与截图对象数量、动作日志，以及队列的待处理数量和最长等待时间均有记录。

走查反馈至少包含：

- 每页总秒数及各阶段秒数的中位数与范围。
- 有源图片、零源图片、需要截图三类页面的耗时差异。
- 来源审核、键盘流或审核闸门中最打断节奏的一处。
- 是否接受当前交互顺序和状态边界作为实现输入。

本次真实走查在剔除启动前等待后测得 5 页中位数 53 秒、范围 14–186 秒：零截图页为 14–23 秒，图片源文件页为 53–186 秒，单个按需截图页为 170 秒。策展人员接受“来源优先、零截图合法”的高层顺序，但首次使用时无法不经讲解完成按需截图。

针对该卡点完成的 A/B/C 原型比较最终选择方案 C，并经两轮细化确认：决策提示贴近中央画面；画框完成后使用不遮挡框选内容的上下文浮窗填写；右栏只保留状态和对象摘要。策展人员已完成最终走查并确认该交互可作为实现输入。

## 8. 原型验证状态

前一轮已验证三栏响应式、批准/排除/重开、批量排除、隐藏页启用、页对应门禁、计时累计和输入焦点保护。按需截图原型与浏览器烟测进一步确认：

- 初始页无截图框，默认展示 AnyDoc 文字与源图片文件。
- 来源审核完成前画框功能锁定。
- 来源完整时零截图可以批准并自动前进。
- 来源审核后可以按需画框，新截图缺少 `summary` 时被阻塞，补齐后阻塞即时清零。
- 松开指针后，上下文浮窗自动避开当前框选并聚焦 `summary`；右栏不承载重复的完整编辑表单。
- 取消首个新框会回到二选一决策，取消追加框会恢复已有完成态，编辑已保存对象时放弃修改不会覆盖原值。
- 已确认来源被再次编辑时，画框和批准会即时重新锁定；零截图通过时，闸门持续提示“来源完整，无需截图即可批准”。
- 源图片互斥处置暴露 `aria-pressed`，阻塞计数通过 polite live region 通知辅助技术。
- 1440 × 1024 与 1280 × 900 视图中，上下文浮窗均不遮挡框选、无裁切或横向溢出；浏览器控制台除缺失 favicon 外无应用错误或警告。

人工结论：方案 C 的中央决策、画框聚光、上下文浮窗填写和紧凑右栏已经确认，可进入实现规划。初版提效能力在此收口为页级继承、待处理队列、零截图快速路径、键盘流、批准后自动前进、上下文浮窗、批量排除及不含事实内容的写作辅助；VLM 和所有跨页批量确认均不进入初版。运行事实只为未来判断提供证据，不承载告警、产能或 SLA 承诺。
