# 逐页策展工作台交互规格

本规格对应 GitHub Issue #7。它记录已选定的 C 版构图、用户确认后的“AnyDoc 来源优先”审核顺序、可交互原型已经验证的行为，以及仍须由策展人员使用本地真实页完成的吞吐验证。

## 1. 目标与边界

工作台服务于熟悉材料的内部策展人员。首版以 1440px 桌面和键盘流为主，在 1280px 下仍保持三栏可用；移动端不在本票范围内。

工作台的目标不是自动替人决定内容，而是让人能在同一视野内完成以下闭环：

1. 对照标准页渲染，先审核 AnyDoc 直接提取的文字与图片源文件。
2. 只有来源不足以表达页面信息时，才手动画框补充截图。
3. 编辑源图片或截图的 `summary`，清空硬校验后批准或排除页面。
4. 记录包含查看、来源审核、可选截图与标注在内的每页总耗时。

原型是单个原生 HTML/CSS/JavaScript 文件，无后端、无持久化。公开内容均为合成样本；从本机载入的 PNG、JPEG 或 WebP 只生成浏览器内存 URL，不上传、不记录文件名。当前静态原型用合成 AnyDoc 数据验证流程，尚未连接真实 AnyDoc 输出。

## 2. 已选构图

采用「页列、画面与纵向日志」：

| 区域 | 1440px 目标占比 | 职责 |
| --- | ---: | --- |
| 左侧页列 | 约 14% | 队列筛选、页码直达、缩略预览、批量选择 |
| 中央画面 | 约 56% | 标准页渲染；来源审核完成后承载可选截图框 |
| 右侧纵向日志 | 约 30% | 默认展示 AnyDoc 文字与图片源文件；第二页签承载按需截图；底部固定审核闸门 |
| 底部命令条 | 固定高度 | 高频快捷键与保存状态 |

视觉语法采用「样片审看室」：中性监看器黑承载来源页，明亮场记纸承载审核记录，teal 表示当前选择，amber 表示待确认，red 表示排除。颜色始终与文字、图形或状态名共同出现。

1280px 时三栏缩为 178px / 可伸缩中央区 / 352px；页面无横向溢出。右侧日志独立滚动，中央来源页不会因长表单被推出首屏。

## 3. 信息模型

### 3.1 页面

页面在策展队列中的审核状态只有：

| 状态 | 可编辑 | 进入方式 | 离开方式 |
| --- | --- | --- | --- |
| `pending` | 是 | 新页、变化页、人工重开、隐藏页启用 | 批准为 `approved`；带原因排除为 `excluded` |
| `approved` | 否 | 硬校验全部通过后批准 | 人工“重新打开”为 `pending` |
| `excluded` | 否 | 选择页级排除原因后排除 | 人工“重新打开”为 `pending` |

隐藏页不是第四种审核结论。它默认只登记为 `hidden`，不进入待处理队列；人工选择“启用并处理此页”后才转为 `pending`。

页面保留可选 `overview`、只读演讲者备注、整页排除原因与补充说明。渲染质量警告需在版本发布前显式确认，但不阻止页内审核或形成页级结论。

### 3.2 AnyDoc 来源审核

每次进入 `pending` 页，右侧默认打开“AnyDoc 来源”，中央页不显示任何自动候选框。来源审核分两类证据：

- **文字提取**：展示 AnyDoc 的当前页原文；人可修订并显式确认。修改已确认文字会立即撤销确认。
- **图片源文件**：逐个展示稳定编号、原始文件名、格式、尺寸和预览。人选择“保留源文件”或“忽略”。

源图片处置规则：

| 处置 | 必填 | 结果 |
| --- | --- | --- |
| 保留源文件 | `summary` | 原始图片文件及人工标注进入产物 |
| 忽略 | 忽略原因 | 文件不进入产物，但保留人工处置审计信息 |

文字与全部源图片处置完整后，人才能点击“完成来源审核”。任何来源字段之后被修改，`sourceReviewConfirmed` 立即回到 `false`，画框入口重新锁定。

### 3.3 按需截图对象

截图不是进入页面时的默认识别结果。只有 `sourceReviewConfirmed = true` 后，人才能点击“按需画框截图”或工具栏“画框截图”，在中央页面拖拽创建截图对象。

手动画框本身即表示“有必要纳入”，因此不再要求对截图对象二次选择纳入或排除。对象支持：

- 拖动或键盘微调位置。
- 拖动右下角或键盘调整尺寸。
- 合并相邻截图。
- 上移、下移或按页面位置排序，改变 `visuals[]` 的阅读顺序。
- 删除不再需要的截图。

每个截图对象保留稳定、可见的两位编号，并在中央定位框与右侧截图日志间一一对应。截图必须填写 `summary`，`visual_type` 可选。页面可以完全没有截图；若 AnyDoc 来源已经足够，零截图是合法、可批准的状态。

### 3.4 VLM 草稿

VLM 只为人工创建的截图对象提供标注草稿，不作审核决定：

1. 仅在人点击“显式生成 VLM 草稿”或按 `V` 时触发。
2. 返回内容显示为“VLM 草稿 · 未确认”，不直接写入正式字段。
3. 人可以采用到 `summary` 后继续修改，或丢弃草稿。
4. 未确认、未丢弃的草稿是硬阻塞。
5. VLM 不触发画框、不生成候选对象，也不自动批准页面。

## 4. 核心流程

### 4.1 进入队列

默认筛选为“待处理”。未变化且已继承的页面不占用主队列，可在“已继承”或“全部”中查看。变化页在页列中同时显示“待审核”和“已变化”。

进入一页时：

- 启动该页计时。
- 默认打开“AnyDoc 来源”页签。
- 中央只呈现标准页渲染，不显示任何自动候选框。
- “画框截图”与“合并截图”保持禁用。
- 不自动触发模型草稿。

### 4.2 来源优先路径

推荐顺序：

1. 对照中央标准页，核对或修订 AnyDoc 文字并确认。
2. 逐个检查图片源文件，保留时填写 `summary`，忽略时选择原因。
3. 点击“完成来源审核”。
4. 判断来源是否已经完整：若是，直接批准；若否，再进入“按需截图”。

### 4.3 可选截图路径

来源审核完成后：

1. 点击“按需画框截图”。
2. 在中央页拖出缺失的组合视觉范围。
3. 为新截图填写 `summary`，需要时调整、合并或排序。
4. 可显式请求 VLM 草稿，但必须采用或丢弃。
5. 返回审核闸门完成页级结论。

### 4.4 审核闸门

审核闸门集中显示所有硬阻塞。以下情况阻止批准：

- AnyDoc 文字尚未确认。
- 任一源图片尚未选择保留或忽略。
- 保留的源图片缺少 `summary`。
- 忽略的源图片缺少忽略原因。
- 来源字段完整但尚未点击“完成来源审核”。
- 任一手动画框截图缺少 `summary`。
- 任一截图的 VLM 草稿尚未确认或丢弃。

不存在“至少一个截图”的要求。写作风格、页级 `overview` 和截图数量只提示，不阻止批准。

审核闸门固定在右栏底部。点击“批准并前进”后，当前页转为 `approved`、记录耗时并进入下一 `pending` 页。点击“排除并前进”前必须选择页级排除原因。`approved` 或 `excluded` 页全部锁定，只有“重新打开”才能恢复编辑。

### 4.5 批量操作与页对应确认

页列允许批量选择。批量排除只作用于所选 `pending` 页，并要求先选择统一排除原因；首版不提供批量批准。

新版本处于 `awaiting_mapping` 时，页对应模式保持模态门禁。歧义项同时展示新版本源页、候选旧页、SlideID、相邻页证据、相对顺序偏移和页指纹变化；全部确认后才返回工作台。

## 5. 键盘与焦点

| 按键 | 动作 |
| --- | --- |
| `←` / `→` | 上一页 / 下一页 |
| `A` | 批准当前页 |
| `X` | 排除当前页 |
| `R` | 重新打开当前页 |
| `V` | 为当前截图显式生成 VLM 草稿 |
| `Esc` | 退出画框模式或关闭状态抽屉 |
| `Shift` + 方向键 | 微调当前截图位置 |
| `Alt` + 方向键 | 微调当前截图宽高 |

当焦点位于 `input`、`textarea` 或 `select` 时，全局快捷键不响应。所有状态必须有可读名称，焦点使用高对比轮廓，按钮禁用状态不能只通过降低颜色饱和度表达。

## 6. 耗时口径与状态导出

计时从进入页面开始，在批准或排除时结束。离开未完成页面时累计本次停留，重新进入后从累计值继续。计时必须包含：

- 查看标准页渲染。
- 核对、修订和确认 AnyDoc 文字。
- 逐个审核图片源文件。
- 必要时画框、裁剪、合并、排序和标注截图。
- 处理 VLM 草稿与页级结论。

每次完成写入页码、秒数和结果。顶栏显示本次会话的完成页平均秒数；“原型状态 JSON”抽屉暴露 `reviewedDurations` 和 `actionLog`。批量排除为每一页单独记录，并以 `mode: "batch"` 标明来源。

浏览器自动化烟测只验证计时记录会生成，不代表人的处理速度。票据完成前仍需由策展人员使用本地真实页完成一次人工走查。

## 7. 人工验收脚本

建议选择 5–10 张本地真实页渲染，至少覆盖：纯文字页、含独立图片源文件页、需要保留组合视觉的页面、演讲者备注、未变化继承页、变化页和隐藏页。

1. 打开原型，在“载入本地页”中选择本机 PNG、JPEG 或 WebP。
2. 完成一页 AnyDoc 文字与图片源文件审核，在零截图状态直接批准。
3. 另选一页完成来源审核后，按需画出至少一个截图并填写 `summary`。
4. 至少触发一次 VLM 草稿并采用或丢弃。
5. 带原因排除一页、重新打开一页，验证隐藏页只有启用后才进入队列。
6. 完成一项页对应确认。
7. 打开状态 JSON，记录每页 `seconds`、是否使用截图及主要卡点。

走查反馈至少包含：

- 每页秒数的中位数与范围。
- 有源图片、零源图片、需要截图三类页面的耗时差异。
- 来源审核、键盘流或审核闸门中最打断节奏的一处。
- 是否接受当前交互顺序和状态边界作为实现输入。

## 8. 原型验证状态

前一轮已验证三栏响应式、批准/排除/重开、批量排除、隐藏页启用、页对应门禁、计时累计和输入焦点保护。本轮浏览器烟测进一步确认：

- 初始页无截图框，默认展示 AnyDoc 文字与源图片文件。
- 来源审核完成前画框功能锁定。
- 来源完整时零截图可以批准并自动前进。
- 来源审核后可以按需画框，新截图缺少 `summary` 时被阻塞，补齐后阻塞即时清零。
- 已确认来源被再次编辑时，画框和批准会即时重新锁定；零截图通过时，闸门持续提示“来源完整，无需截图即可批准”。
- 源图片互斥处置暴露 `aria-pressed`，阻塞计数通过 polite live region 通知辅助技术。
- 1440px 与 1280px 视图均无横向溢出，浏览器控制台无错误或警告。
