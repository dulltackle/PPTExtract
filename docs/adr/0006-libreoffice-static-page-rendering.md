# 用 LibreOffice 生成静态标准页渲染结果

审核界面和人工截图资产需要同一份规范页图，而 anydoc 不负责视觉渲染。我们决定初版用精确锁定的 LibreOffice headless 把 `.pptx` 转为中间 PDF，再由精确锁定的 Poppler 以 144 DPI 生成 PNG 标准页渲染结果；保持源页比例和物理尺寸，不为得到固定的 1920 像素宽而缩放或裁切。5 份本地代表性样本共 200 页均成功生成，43 页样本的两次 PDF 字节不同、逐页 PNG 字节却完全一致，因此 PDF 只作中间产物，PNG 才是审核、缓存和人工截图资产裁剪的基准。AnyDoc 来源图片资产不经过本渲染链路，见 ADR-0008。

## 渲染契约

- 标准页渲染结果是静态打印状态。动画时间线、过渡和运动语义不进入 Chunk，也不生成多帧资产；检测到动画时间线时记录渲染警告。
- 渲染前审计源字体，渲染后记录实际字体替代。缺失或替代字体形成渲染警告，不得静默忽略。
- 渲染警告不阻止版本成为 ready 或进入策展，但存在未确认渲染警告时发布硬校验必须失败。确认记录操作人、时间、警告明细和渲染配置版本，并在摄取与审核界面持续可见。
- LibreOffice 构建、字体包、PDF 导出参数、Poppler 构建和 DPI 共同组成带版本的渲染配置。缓存键必须包含页来源、渲染配置版本和渲染选择；任一项变化都使标准页渲染结果及其人工截图资产缓存失效。
- 渲染工具链镜像只在工具链升级时构建、验证并发布一次；生产、CI 和开发环境必须按完整的 registry SHA-256 digest 拉取同一产物。常规契约门禁不得现场重建镜像，也不得把引擎相关的本地 image ID 当作发布身份，因为构建时间和层元数据会使语义相同的构建产生不同 ID。
- 渲染配置变化不改变页指纹，也不改变 ADR-0004 的审核继承规则；需要按既有裁剪范围确定性重建人工截图资产，但不得改写或重建 AnyDoc 来源图片资产。新的渲染配置只有通过公开合成样本和代表性本地样本的人工视觉门禁后才能部署。
- 渲染任务按页保存检查点并报告已完成页数。完整样本的单文档渲染耗时为 22 至 100 秒，审核界面不得用无阶段、无进度的同步等待掩盖这段时间。

## Considered Options

ONLYOFFICE Docs 能自托管并直接生成逐页图片，但需要常驻 DocumentServer、JWT 和可访问的输入 URL，Community 版还带来 AGPLv3 义务；Aspose.Slides 可以离线嵌入并直接生成逐页图片，但需要商业许可；Microsoft Graph 依赖 Microsoft 365 和云端文件传输，不符合默认离线自托管边界。LibreOffice 的部署与许可负担最低，代价是不能承诺与 PowerPoint 视觉等价，因此字体报告、渲染警告和模板视觉门禁都是选型的一部分，而不是后续优化。
