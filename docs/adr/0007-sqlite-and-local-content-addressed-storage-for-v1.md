# 初版使用 SQLite 与本地内容寻址存储

ADR-0005 的 PostgreSQL 与 S3 兼容对象存储方案能支持多实例、跨主机共享和较强的灾难恢复目标，但这些能力超出初版验证人工策展、持久任务与原子发布闭环的必要范围。我们决定将初版限定为单机、单 worker 部署：SQLite 是结构化状态和持久任务的唯一权威来源，同一台机器的本地持久目录保存内容寻址二进制。初版不实现 PostgreSQL 或 S3 兼容存储。本 ADR 取代 ADR-0005。

## 部署与存储边界

- FastAPI API 与一个持久任务 worker 可以是独立进程，但必须运行在同一台机器上，并共享同一个本地持久卷。SQLite 数据库和二进制目录不得放在临时目录或网络文件系统上。
- SQLite 启用 WAL、外键校验和有界的 busy timeout。所有写事务必须保持短小；转换、渲染与 ZIP 构建不得持有数据库事务。
- 摄取和发布任务仍是至少一次交付的持久任务。worker 通过 SQLite 兼容的短事务和条件更新原子认领单个任务，不使用 `FOR UPDATE SKIP LOCKED`；租约、尝试次数、阶段进度和页级检查点仍持久化。
- “持久”修饰任务、租约与检查点；worker 是可随时重启或替换的执行者，其进程内状态不是恢复依据。

## 二进制对象

- 原始 `.pptx`、单页投影、标准页渲染结果、视觉资产与产物 ZIP 保存在本地持久目录，数据库只保存对象键、SHA-256、字节数、媒体类型和校验状态。
- 对象先写入同一文件系统中的临时路径，完整刷盘并校验后原子重命名到不可变内容键。数据库事务随后建立业务引用；事务失败留下的无引用文件由延迟可达性回收清理。
- 本地持久目录是初版的正式二进制存储，不是可丢弃缓存。仅 OOXML 解包、转换工作区与 ZIP 组装中间目录可在进程退出后丢弃。

## 备份与恢复

- 初版不承诺 ADR-0005 中的 `RPO ≤ 5 分钟、RTO ≤ 4 小时`。备份必须协调捕获 SQLite 一致快照和同期本地对象，不得只备份其中一方。
- 恢复后在重新开放写入和发布前，仍要审计原始 `.pptx`、正式视觉资产、发布冻结成员和当前产物的存在性、大小与 SHA-256；审计失败时保持不可发布。

## Consequences

这个选择保留崩溃续跑、审计历史、完整性校验、版本生效与当前产物指针的原子切换，同时去掉 PostgreSQL 和 S3 兼容服务的初版运维成本。代价是初版不支持多主机、多 worker、水平扩展、对象存储版本控制或托管高可用；数据库文件、WAL 与对象目录也变成必须整体备份的单机数据集。

当部署需要跨主机共享状态或二进制、并行 worker、托管高可用或明确 RPO/RTO 时，必须通过新 ADR 重新评估 PostgreSQL 与 S3 兼容存储，不得在不改变本 ADR 的情况下增加第二个 worker 或网络文件系统。

## Considered Options

- **PostgreSQL + S3 兼容存储**：保留为未来扩展候选，但初版不为尚未确认的多机、吞吐或高可用需求承担运维代价。
- **SQLite 内保存二进制 BLOB**：可以共享单个事务边界，但会放大数据库、WAL 和备份成本，也不利于流式与 Range 下载。
- **只保存临时文件**：无法支持崩溃续跑、不可变历史或产物下载，与已确认的产品语义冲突。
