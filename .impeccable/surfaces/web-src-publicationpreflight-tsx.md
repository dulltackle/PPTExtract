# 冻结发布台账

- **范围 / 模式**：工作区级 React 工作面；Operate。1440px 为主，1280px 保持候选台账与控制栏并列可读；移动端不在首次发布范围。
- **用户与任务**：发布操作者先审阅当前一致视图及排除项，再明确创建候选、确认冻结，并观察不可变完整产物构建到切换完成。
- **已确认方向**：延续现有深色工作台框架，在浅色纸张式台账中按文档、版本、页面展开候选范围；右侧固定为确认与四阶段任务轨道，当前产物以顶部状态条持续可见。
- **真实性边界**：创建候选和确认发布都是显式人工动作；确认后冻结精确 chunk、快照与视觉资产；失败时当前产物不变；重试复用同一冻结输入和序号。
- **视觉验收**：1440×1024 与 1280×900 均不得出现页面级横向溢出；长哈希、错误信息和页面明细可折行或在局部容器内安全滚动。

## 方向契约

- **THESIS**：发布不是一个按钮，而是一笔可核验、可追溯、失败安全的冻结账目。
- **FIRST VIEWPORT**：首先展示当前产物及其序号/哈希；主体左侧给出候选差异、排除原因和可展开页清单，右侧给出下一步动作与发布阶段。
- **KEY STATES**：无当前产物、无候选、候选待确认、候选过期、排队、冻结、构建、校验、切换成功、失败但当前不变、基于同一冻结输入重试。
- **KEYBOARD**：所有披露、确认与重试控件使用原生按钮/表单语义，并提供可见焦点；确认必须在内联确认区再次提交。
- **FINAL REVIEW**：确认区必须复述文档/页面/chunk/资产计数和将要保留的当前产物；完成态展示新序号、产物哈希及一致性校验结果。
