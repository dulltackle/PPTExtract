# 来源文字核对稿

## 范围与模式

- 适用于 React 策展工作台右侧来源日志中的标题与正文核对路径。
- 界面模式为 Operate：高密度、键盘可达、以完成核对和修订为目标。
- 不改变备注、表格、图片、捕获记录与最终决策等其他区域。

## 已确认方向

- 延续“样片审看室”视觉系统：深色监看台承载浅色稿纸，青色表示当前操作，琥珀色表示待处理。
- 标题在前、正文在后，采用无卡片的连续核对稿；以 1 个标题、11 个正文块和长文本作为压力基线。
- 编号轨道始终可见且弱化：标题使用“标题 1”，正文使用“正文 01”起的稳定编号。
- 全文自然换行，不截断、不折叠、不摘要、不合并、不重排；空块仍保留身份。
- 紧凑预览中的主文字可点击；正文放大视图把全部正文块呈现在同一个连续稿纸表面，来源段号与细分隔线持续标示稳定边界，不退化为卡片列表。
- Enter 与多行粘贴只修改当前来源文字块；允许跨块选择和复制，但跨块输入、粘贴、剪切、Backspace 与 Delete 整次拒绝，且不改变选区或焦点。
- 边界阻止提示固定在正文放大视图底部，通过状态区域宣布，不使用弹窗或浮动 toast，也不堆积重复消息。
- 关闭正文放大视图、失焦与 Escape 只结束当前编辑状态并保留页级本地草稿；只有统一保存持久化，现有还原流程才丢弃草稿。
- 正文来源段号是逐块审计入口；未修改保持普通编号，已修改与当前为空分别用低调且不同形状的标记表达，正文不常驻显示行内差异。
- 来源审计从右侧工作区内滑入并覆盖正文区域，标准页渲染结果继续可见；当前值与 AnyDoc 原文在宽工作区并排、较窄桌面宽度下上下排列。
- 来源审计约束键盘焦点，Escape 逐层关闭并把焦点精确恢复到打开它的来源段号；打开和关闭不保存、不还原，也不丢弃整稿本地草稿。
- 重复页脚检查、确认状态、受影响页和撤销入口仅出现在对应来源的审计面板，不在正文保留常驻次级动作。
- 已确认内容默认只读，必须经“修改文字”边界并明确提示会使既有确认失效后才能再次编辑。
- 1280 宽度维持三栏工作台；模拟 200% 文字缩放时三栏保留工作区内部横向滚动，核对块改单列且页面无横向溢出。
